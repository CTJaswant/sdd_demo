---

## The SDD Artifact Chain

```
CLAUDE.md                         ← project governance (auto-loaded every session)
      ↓
RISK-CLASSIFICATION.md            ← classify risk before writing anything
      ↓
SPEC.md  ──── /sdd-clarify        ← what the feature does
      ↓
DESIGN-NOTE.md + PLAN.md          ← how + safety design
      ↓
TASKS.md ──── /sdd-analyze        ← ordered executable steps
      ↓
IMPLEMENT ─── PostToolUse hook    ← build verified on every file write
          ─── /spec-review        ← AC check after each phase
          ─── /hipaa-check        ← compliance gate before merge
          ─── worktree + subagent ← controller in isolated workspace
      ↓
REVIEW subagent                   ← independent review before eval
      ↓
EVAL.md                           ← evidence + provenance before PR
      ↓
PR                                ← integrate and close the loop
```

**Each artifact is a gate. Do not proceed until the current one is complete.**


Write this yourself — do not paste, do not use Claude:

```markdown
# Intent — Member Eligibility Phase 1

## Problem
Non-clinical agents submitting PA requests cannot verify member coverage
before submitting. Requests are submitted blind — wasting time when
coverage does not exist.

## Users
Non-clinical agents creating prior authorization requests.

## Proposed Solution
A local database lookup that checks whether a member is eligible
under their health plan before the PA request is submitted.
Phase 1: local DB only. No real-time health plan API calls.

## Success Criteria
Agent sends a request with memberId and health plan details.
System returns a deterministic status: ELIGIBLE, INELIGIBLE, or ERROR.
Every check is audited. No PHI appears in logs.

## Known Non-Goals
- Real-time health plan API
- React UI changes
- Caching
```

Save. This is your intent. Claude generates the spec from this.

```
Before writing any code read:

  specs/001-member-eligibility/spec.md       ← API contract + ACs + error codes
  specs/001-member-eligibility/design-note.md ← audit requirements
  CLAUDE.md                                  ← compliance rules

Create Controllers/EligibilityController.cs:

[ApiController]
[Route("api/eligibility")]
public class EligibilityController : ControllerBase

Constructor inject: PriorAuthDbContext _db, ILogger<EligibilityController> _logger

[HttpPost("check")] → ActionResult<EligibilityCheckResponse>

Lookup logic in this exact order:
  1. memberId not found → ERROR, errorCode MBR-001
  2. dateOfBirth mismatch → ERROR, errorCode MBR-002
  3. healthPlanId mismatch → INELIGIBLE, errorCode PLY-001
  4. All match → ELIGIBLE with memberName, policyStatus,
     effectiveDate, terminationDate from member record

CorrelationId: use from request or Guid.NewGuid().ToString()

Audit log — ONE entry per call:

    "EligibilityCheck {CorrelationId} {Status}", correlationId, status)

Audit record — write to DB:
  _db.EligibilityRecords.Add(new EligibilityRecord {
    MemberId = request.MemberId,
    CorrelationId = correlationId,
    Status = result.Status,
    CheckedAt = DateTime.UtcNow,
    DataSource = "LOCAL"
  });
  await _db.SaveChangesAsync();

dataSource = "LOCAL", checkedAt = DateTime.UtcNow in response.

Stop after this one file only.
```
